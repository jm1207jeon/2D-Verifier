## 1. 개요

### 1.1 배경
의료기기 생산·검사 현장에서 제품 라벨의 UDI(Unique Device Identification) 바코드(GS1 DataMatrix
등)를 스캔하여 GTIN·LOT·품번(PN)·제조일자·유효기간·시리얼(SN)·UPN을 추출하고, 검사 기록용
라벨 사진을 규칙적인 폴더/파일명으로 보관해야 한다. 범용 스캐너 유틸리티는 다음을 지원하지
못한다.

- 사내 라벨 특유의 **GS 구분자 생략/오배치**(필드가 붙어서 인코딩됨) 대응 파싱
- 스캔값의 **엑셀 자동 입력**(키보드 웨지) 시 Caps Lock 오동작 없는 입력
- 판독과 동시에 같은 위치의 **라벨 사진 자동 촬영·저장**
- 중복 스캔 관리(무시/카운트)와 LOT 단위 묶음 확인

UDI Capture는 이 요구를 하나의 프로그램으로 통합한 현장용 도구다.

### 1.2 목표
1. 트리거 한 번으로 "판독 → 데이터 추출 → 엑셀 입력 → 사진 저장"이 자동으로 완결된다.
2. 사내 라벨 체계(검증 문서 SVRF805032501 기준)의 모든 바코드가 필드 단위로 정확히 분해된다.
3. 스캐너 상태(호스트 모드, 촬영/디코드 모드, 연결)는 프로그램이 스스로 관리하며 사용자가
   손댈 필요가 없다.
4. 설치는 exe 복사 + Zebra 드라이버 설치만으로 끝난다 (.NET 런타임 불필요).

### 1.3 용어
| 용어 | 정의 |
|---|---|
| UDI | 의료기기 고유 식별 코드. GS1 표준 응용식별자(AI) 체계로 인코딩 |
| AI | Application Identifier. 01=GTIN, 10=LOT, 11=제조일, 17=유효기간, 21=SN, 240=PN, 30=UPN 등 |
| GS | Group Separator(0x1D). 가변 길이 AI 값의 종료 구분자 (FNC1) |
| SNAPI | Zebra 스캐너의 USB 호스트 모드. 이미지 캡처·트리거 제어 API 지원 |
| 키보드 웨지 | 스캔값을 포커스된 외부 프로그램(엑셀 등)에 키 입력으로 전달하는 기능 |
| 강제 스캔 | 트리거=촬영 모드. 사진을 먼저 찍고 소프트웨어/하드웨어로 바코드를 인식 |

## 2. 사용 환경 및 전제

- OS: Windows 10 19041 이상 (x64)
- 필수 소프트웨어: **Zebra Scanner SDK for Windows** (CoreScanner 드라이버). 앱은 CoreScanner
  COM API로만 스캐너와 통신한다.
- 스캐너: DS9908 (권장). CoreScanner가 인식하는 타 Zebra 스캐너도 기본 동작은 호환.
- 배포: GitHub Actions가 push마다 자동 빌드하여 `latest-build` 릴리스에
  `UDI-Capture-win-x64.zip` (내부 `UDI Capture_ver.1.exe`) 게시.
- 설정 파일: `%APPDATA%\ZebraScannerSuite\settings.json` (자동 저장, 재실행 시 유지).

## 3. 제품 범위

### 3.1 포함 (In Scope)
- 일반 스캔(단건 작업) / 멀티 스캔(연속 집계) 2개 탭
- GS1 UDI 파싱(표준 + 사내 라벨 특례), 추출 필드 표시
- 이미지 캡처·자동 저장(날짜/LOT 폴더), 인식 위치 바운딩 박스 표시
- 자체 키보드 웨지(SendInput, 값+Enter)
- 중복 스캔 관리(일반: 입력 생략, 멀티: 카운트 증가)
- CSV 내보내기(엑셀 호환 텍스트 처리)
- 스캐너 상태 자동 관리(SNAPI 전환, 재연결 감시, 모드 복구)

### 3.2 제외 (Out of Scope)
- ISO 15415 바코드 품질 검증(초기 버전에서 제거됨)
- OCR(문자 인식) 기능(제거됨)
- 추출 규칙 편집 UI(REGEX/SUBSTR 규칙은 설정 파일 수동 편집으로만 가능)
- 다중 스캐너 동시 운용(첫 번째 스캐너만 제어 대상)
- 스캔 데이터의 서버 전송/DB 연동

## 4. 기능 요구사항

### 4.1 스캐너 연동 (자동 관리)

| ID | 요구사항 |
|---|---|
| SCN-01 | 앱 시작 시 CoreScanner COM에 연결하고 바코드/이미지/PnP 이벤트를 구독한다. |
| SCN-02 | 연결된 스캐너가 SNAPI(이미징) 모드가 아니면 자동으로 `USB SNAPI (이미징 지원)` 모드로 영구 전환한다. 전환 명령 실패 시 상태바에 안내하고 20초 쿨다운 후 자동 재시도한다. |
| SCN-03 | CoreScanner의 HID 키보드 에뮬레이터는 항상 비활성화한다 (Caps Lock 토글 부작용 방지, 자체 웨지로 대체). |
| SCN-04 | 시작/탭 전환/강제 스캔 토글/PnP 재연결 시 `EnsureScannerMode`가 목표 상태(디코드 vs 촬영 모드, 비프 설정, ScanEnable)를 최대 5회(700ms 간격) 재시도로 보장한다. 재시도 루프는 재진입이 방지되며, 진행 중 들어온 새 요청은 보류 후 종료 즉시 최신 UI 상태로 재실행된다. |
| SCN-05 | 10초 주기 감시 타이머: 연동 실패 시 재초기화, 스캐너 목록이 비면 재검색 후 모드 복구. (수동 "새로고침" 버튼 없음) |
| SCN-06 | 종료 시 디코드 모드/비프를 복원하고 COM 리소스를 해제한다. |
| SCN-07 | 상태바에 스캐너 모델·시리얼·호스트 모드를 상시 표시한다. |

### 4.2 일반 스캔 탭

#### 4.2.1 동작 모드
| ID | 요구사항 |
|---|---|
| GEN-01 | 라디오 버튼 2종: **바코드 리딩** / **바코드 리딩 + 이미지 캡처**. 후자는 디코드 직후 같은 위치를 자동 촬영하여 저장한다 (수동 트리거 불필요, 촬영 명령 지연 35ms + 모드 안정화 15ms). |
| GEN-02 | **강제 스캔 (F9)**: 켜면 트리거=촬영. 촬영 이미지에서 ①고속 SW 디코드 → ②실패 시 하드웨어 재판독(600ms) → ③정밀 SW 디코드(TryHarder+대비 보정) 순으로 인식하고, 인식 여부와 무관하게 이미지는 항상 저장한다(미인식 시 파일명 `NOCODE`). |
| GEN-03 | **중복값 무시** (기본 ON): 이미 스캔한 값은 화면 표시·기존 행 하이라이트만 하고 키보드 입력을 생략한다. OFF면 중복도 입력된다. |
| GEN-04 | 키보드 웨지는 항상 활성(별도 옵션 없음): 앱이 비활성 창일 때 스캔값+Enter를 포커스된 커서 위치에 유니코드 SendInput으로 입력한다. Caps Lock/IME 상태에 영향을 주지 않는다. |

#### 4.2.2 판독 결과 표시
| ID | 요구사항 |
|---|---|
| GEN-05 | 바코드 원문을 큰 글씨로 표시하되 GS1 AI(01,10,11,17,21,240,30 등)는 **빨간색**으로 강조한다. GS 구분자는 표시하지 않는다. |
| GEN-06 | 심볼로지 명칭(GS1 DataMatrix 등)과 하드웨어 TYPE 코드를 표시한다. |
| GEN-07 | **UDI 데이터** 그리드: GTIN(01)/LOT(10)/PN(240)/MFG DATE(11)/EXP DATE(17)/SN(21)/UPN(30)을 행 단위로 표시. 날짜는 `YYYY-MM-DD`로 변환. |
| GEN-08 | **실시간 목록**: LOT/EXP/PN/SN 4열. 신규 스캔은 행 추가+하이라이트 페이드(650ms), 중복은 기존 행 하이라이트만. 연속된 같은 LOT는 같은 배경색으로 묶고 LOT가 바뀌면 배경색을 교대(흰색↔연한 파랑)하여 묶음을 구분한다. "지우기" 버튼으로 목록·중복 기록 초기화. |
| GEN-09 | HID 키보드 입력창: 스캐너가 HID 모드일 때 이 칸에 스캔하면(Enter 종료) 동일한 처리 흐름을 탄다 (폴백 경로). |

#### 4.2.3 캡처 이미지
| ID | 요구사항 |
|---|---|
| GEN-10 | 촬영 이미지를 좌측 영역에 표시한다. 저장 파일은 원본 그대로 유지한다. |
| GEN-11 | 인식된 바코드 위치에 은은한 주황색 반투명 바운딩 박스를 표시한다(화면 전용). 위치는 SW 디코더가 제공하며, 일반 모드에서는 배경 스레드에서 탐색 후 갱신하므로 판독·저장 속도에 영향이 없다. SW 디코더가 위치를 찾지 못하면 박스 없이 표시한다. |

### 4.3 이미지 저장

| ID | 요구사항 |
|---|---|
| IMG-01 | 저장 경로는 사용자가 지정하며 재실행 시에도 유지된다 (기본: `사진\ZebraScans`). |
| IMG-02 | **날짜 폴더로 저장** (기본 ON): 경로 아래 `YYYY-MM-DD` 폴더를 자동 생성해 저장. |
| IMG-03 | **LOT 폴더로 저장** (기본 OFF): UDI에서 추출한 LOT값(8자리 숫자 또는 `01P…` 전체 텍스트) 폴더를 자동 생성해 저장. 날짜 폴더와 동시 사용 시 `날짜\LOT` 순으로 중첩. LOT가 없으면 상위 폴더에 저장. |
| IMG-04 | 파일명 규칙: `{날짜(yyyyMMdd)}_{바코드값}_{순번 3자리}` 고정(내부 규칙, UI 편집 없음). 파일명에 쓸 수 없는 문자·GS는 `_`로 치환, 80자 초과 시 절단. 중복 시 순번 자동 증가(폴더 목록 1회 스캔으로 고속 판정). |
| IMG-05 | 확장자는 이미지 바이트의 매직 넘버로 자동 판별(JPG/BMP/PNG/TIF). |
| IMG-06 | 저장 실패(권한/네트워크 등) 시 상태바에 오류를 표시한다. |

### 4.4 멀티 스캔 탭 (연속 집계)

| ID | 요구사항 |
|---|---|
| MUL-01 | 탭 진입만으로 자동 준비(버튼 없음): 디코드 모드 + 스캐너 자체 비프 OFF. 탭 이탈 시 일반 설정으로 복원. |
| MUL-02 | 트리거 1회 = 1회 판독. 신규 바코드만 앱이 비프 1회를 울리고, 중복은 무음으로 해당 행의 횟수만 증가시킨다. |
| MUL-03 | 목록 열: No.(우측 정렬)/시간/GTIN/LOT/MFG/EXP/PN/SN(우측)/UPN/원본/횟수(우측). 중복 판정 키는 심볼로지+원문. 판독 시 해당 행 하이라이트 페이드. |
| MUL-04 | 고유 판독 수를 대형 주황 숫자로, 총 읽음 횟수를 별도로 표시한다. |
| MUL-05 | **CSV 내보내기**: UTF-8(BOM). GTIN/LOT/PN/SN/UPN/원본은 `="값"` 수식 형태로 저장하여 엑셀의 지수 표기·앞자리 0 소실을 방지한다. 파일이 사용 중이면 "다른 프로그램에서 열려 있는지 확인" 안내를 표시한다. |
| MUL-06 | **사진 저장** 옵션(설정 유지): 켜면 판독 직후 같은 위치를 배경에서 자동 촬영해 이미지 저장 규칙(4.3)대로 저장한다. 화면에는 표시하지 않으며, 진행 중 촬영은 1건씩(3초 미수신 시 자동 해제) 처리한다. |
| MUL-07 | "목록 지우기"로 목록·카운트 초기화. |

### 4.5 GS1 UDI 파싱 규칙

#### 4.5.1 표준 파싱
| ID | 요구사항 |
|---|---|
| PRS-01 | AIM 심볼로지 접두(`]d2` 등)와 괄호 표기 `(01)…`를 정규화한다. |
| PRS-02 | 고정 길이 AI(00,01,02,11,12,13,15,16,17,20,410~417,8005 등)와 가변 길이 AI(10,21,22,30,37,90~99, 235,240~255,400~427,710~715, 7001~8200 계열)를 지원한다. 계량형 31xx~36xx도 인식한다. |
| PRS-03 | 가변 길이 값은 GS(0x1D) 또는 데이터 끝에서 종료된다. |
| PRS-04 | 날짜(YYMMDD)는 `YYYY-MM-DD`로 변환한다. 세기는 현재 연도 기준 [-49, +50]년 슬라이딩 윈도우로 판단한다(2050년대 이후에도 안전). DD=00이면 `YYYY-MM`. |

#### 4.5.2 사내 라벨 특례 (검증 문서 SVRF805032501 기준)
사내 라벨은 GS 구분자가 생략되거나 끝에 잉여 GS가 붙는 형태가 존재한다. 고정폭 규격
(LOT 8자리, PN 7자, SN 1~2자리 숫자, UPN은 'M'으로 시작)을 근거로 다음 특례를 적용한다.

| ID | 요구사항 |
|---|---|
| PRS-05 | **LOT 8자리 고정**: AI 10 값이 GS 없이 8자를 초과하면 앞 8자만 LOT로 취하고 나머지는 되돌려 다음 AI(17/11/240/21…)로 계속 파싱한다. 예) `10 25081215 17 280928 240 11c0803 21 7` |
| PRS-06 | **SN+UPN 분리**: AI 21 값이 `숫자1~2 + "30" + "M…"` 형태면 GS 종결 여부와 무관하게 SN과 UPN(AI 30)으로 분리한다 (라벨 끝 잉여 GS 대응). |
| PRS-07 | **PN 꼬리 분리**: AI 240 값 끝의 `"21"+SN(1~2자리)[+"30"+"M…"]`을 분리한다. 예) `24001-0854211` → PN=01-0854, SN=1. 강한 패턴(30+M 포함)은 GS 종결 값에도 적용, 약한 패턴(21+SN만)은 GS로 끝나지 않은 값에만 적용한다. |
| PRS-08 | 특례 정규식은 값 길이 40자 이하에서만 동작한다 (표준 라벨의 우연한 오분리 방지 안전장치). |
| PRS-09 | **스텐트 반제품**: `01P`로 시작하는 바코드는 AI 파싱 없이 전체 값을 LOT로 취급한다. |
| PRS-10 | 수신 원문에서 CR/LF 등 제어문자는 제거하되 GS(0x1D)는 파싱 단계까지 보존한다 (표시는 한 줄). |

#### 4.5.3 검증된 파싱 예시 (회귀 기준)
| 입력(요약) | 기대 결과 |
|---|---|
| `01…7654 10 25081215 17 280928 240 11c0803 21 7` (GS 없음) | LOT=25081215, EXP=280928, PN=11c0803, SN=7 |
| `01…4402 10 25040980 17 280408 11 250409 240 01-0854 21 1` (GS 없음) | PN=01-0854, SN=1 |

## 8. 알려진 제한사항

1. **바운딩 박스**는 소프트웨어 디코더가 위치를 찾은 경우에만 표시된다 (스캐너 하드웨어는 좌표를 제공하지 않음).
2. **다중 스캐너**: 첫 번째로 검색된 스캐너만 제어한다.
3. **추출 규칙 편집 UI 없음**: 기본 7개 필드 고정. REGEX/SUBSTR 규칙은 settings.json 수동 편집 필요.
4. 특례 파싱은 사내 라벨 규격(LOT 8자, SN 1~2자, UPN=M접두)에 최적화되어 있다. 규격이 다른
   외부 라벨은 표준 GS1 규칙으로만 파싱된다.
5. 강제 스캔의 소프트웨어 인식률은 촬영 품질(거리·조명·초점)에 의존하며 하드웨어 직접 판독보다 낮다.
