# UDI Capture_ver.1 — NB 심사 대응 및 공식 적용 로드맵

| 항목 | 내용 |
|---|---|
| 목적 | 검사 보조 도구 → 품질경영시스템(QMS) 공식 소프트웨어로 승격하기 위한 과제 정리 |
| 규제 근거 | ISO 13485:2016 §4.1.6 (QMS 소프트웨어 밸리데이션), GAMP 5 Category 5 (맞춤형), 21 CFR Part 11 / EU Annex 11 (전자기록), MFDS 의료기기 GMP |
| 문서 상태 | 과제 정의 (2026-08-15) — 각 항목 완료 시 체크 갱신 |

> **분류 원칙**: 이 소프트웨어는 의료기기 자체(SaMD)가 아니라 **QMS에 사용되는 도구**다.
> 따라서 인허가 대상이 아니라 ISO 13485 §4.1.6 밸리데이션 대상이며, NB 심사에서는
> "이 도구의 출력을 품질기록으로 신뢰할 수 있는가"를 소명해야 한다.

> ✅ **U-2 결정 (2026-08-15)**: 본 도구는 **검사 보조 도구**로만 사용한다 (데이터 파싱·
> 가공이 주 목적, 품질기록 원본 미생성). 이에 따라 **위험기반 간이 검증 트랙**을 채택:
> - 정식 문서 세트(C-3~C-9)는 통합 간이 문서 2종으로 대체 — `docs/validation/TOOL_VALIDATION.md`
>   (도구 평가·검증 보고서: URS-lite + 리스크 + 추적성 + 검증 결과 통합),
>   `docs/validation/VERIFICATION_CHECKLIST.md` (실기 확인 기록 양식)
> - Tier 1 규제 기능(감사추적, 로그인, SQLite, 전자서명 등)은 **보류** — 품질기록
>   시스템으로 승격하기로 결정하는 시점에 재개
> - 자동 회귀 테스트(C-1/C-2)는 트랙과 무관하게 계속 운영 (간이 검증의 핵심 근거)

## 2. 단계별 실행 계획

### Phase 0 — 지금 (이 커밋에서 완료)
- ✅ **C-1/C-2**: 자동 회귀 테스트 30여 건 + CI 통합.
  - 커버 범위: GS1 파서(실라벨 12케이스 + 특례 안전장치 + 날짜 슬라이딩 윈도우),
    UDI 추출 7필드, 이미지 저장(확장자/파일명/순번/날짜·LOT 폴더)
  - 효과: 이후 어떤 수정에서도 검증된 라벨 파싱이 깨지면 **배포 자체가 차단**됨.
    CI 실행 로그와 trx 파일이 "회귀 검증 객관적 증거"로 축적됨

### Phase 1 — 문서 기반 구축 (클로드 주도, 1~2주)
- C-3 ~ C-9: URS → FS/DS → RTM → 리스크 → OQ/IQ 문서 초안 일괄 작성
- U-1: 사용자 검토·승인 (문서당 검토 30분~1시간 예상)
- **의사결정 필요(U-2)**: 보조 도구로 유지할 경우 Phase 1의 경량화 가능
  (URS+리스크+간이 검증기록 정도로 축소)

### Phase 2 — 규제 대응 기능 구현 (클로드 주도, 1~2주)
- C-10: 버전 고정 릴리스 (밸리데이션은 "특정 버전"에 대해 수행되므로 선행 필수)
- C-11: 감사추적 → C-13: 데이터 무결성 → C-12: 로그인/권한 (의존 순서)
- C-14: 시뮬레이션 모드 (OQ 자동화 범위 확대)
- 각 기능은 테스트 동반 → CI 증적 자동 축적

### Phase 3 — 검증 실행 (사용자 주도, 1~2주)
- U-3: OQ 실기 (클로드가 만든 프로토콜 그대로 실행·기록)
- U-4: IQ, U-3 연장으로 PQ (실제 생산 3~5 배치 병행 운영)
- 클로드: 결과 취합 → 밸리데이션 보고서(VR) 초안

### Phase 4 — 공식 적용 (사용자 주도)
- U-5 SOP 편입 → U-6 교육 → 공식 사용 개시 선언
- 이후 변경 시: 코드 수정 → CI 회귀 통과 → 영향평가(클로드 초안) → 승인(사용자) → 재검증 범위 결정

**총 소요 감각**: 품질기록 시스템 승격 기준 실working일 4~6주 (문서 승인·실기 검증이 지배적).
보조 도구 유지 시 1~2주.

## 3. 테스트 전략 — 자동화 범위 최대화

| 계층 | 내용 | 수행 주체 | 상태 |
|---|---|---|---|
| L1 단위(로직) | 파서·추출·저장 규칙. 실라벨 회귀 케이스 고정 | **클로드+CI 완전 자동** | ✅ 운영 중 |
| L2 통합(무장비) | 시뮬레이션 모드로 스캔→표시→중복→목록→CSV 전 흐름 검증 | **클로드+CI 자동** (C-14 후) | ☐ |
| L3 정적 | 컴파일 경고=오류, 분석기, 모델 교차 코드리뷰 | **클로드 자동** | △ 부분 운영 |
| L4 장비 연동 | 실스캐너 디코드/촬영/모드 전환/PnP 복구 | **사용자 실기** (OQ) | ☐ |
| L5 실사용(PQ) | 실제 생산 라벨·작업 패턴으로 병행 운영 | **사용자 실기** | ☐ |

원칙: **L1~L3를 최대한 두껍게** 만들어 사용자 실기(L4~L5)는 "장비가 아니면 확인 불가능한
것"으로만 좁힌다. 새 라벨 유형·파싱 이슈가 나올 때마다 L1에 케이스를 추가해 영구 고정한다.

## 5. NB 심사 예상 질의 대비 (요지)

1. **"이 소프트웨어는 밸리데이션 되었는가?"** → 밸리데이션 패키지(URS~VR) + CI 회귀 증적 제시
2. **"누가 개발했고 어떻게 관리되는가?"** → 사내 개발 + AI 지원 도구 사용, git 형상관리,
   자동 회귀 테스트, 변경통제 절차 연결 설명 (AI 사용 자체는 문제가 아니며, *검증 체계*가 답변의 핵심)
3. **"데이터를 신뢰할 수 있는가?"** → 감사추적/무결성 기능(Phase 2) + 파서 회귀 테스트
4. **"고장 나면 검사가 중단되는가?"** → 보조 도구 포지션 + 수기 대체 절차(SOP에 명시)
5. **"버전은 어떻게 통제되는가?"** → 태그 릴리스 + 체크섬 + IQ 대조
